> 测试环境：Debian GNU/Linux 13 (trixie) x86_64，VMware 虚拟机

## 5.1　测试环境

| 项目 | 值 |
| --- | --- |
| 操作系统 | Debian GNU/Linux 13 (trixie) |
| 架构 | x86_64 |
| 虚拟化 | VMware |
| CPU / 内存 | 6 vCPU / 5.8 GiB |
| GTK | 3.24.49 |
| 块设备 | `/dev/sda`（200 GiB，系统盘）、`/dev/sr0`（VMware Tools ISO） |
| 测试介质 | 回环设备 `/dev/loop0`（512 MiB）、`/dev/loop1`（200 MiB） |

**测试方法**：虚拟机没有物理 USB 设备，全部破坏性测试都在 `losetup`
创建的回环块设备上进行。回环设备对内核而言是**真正的块设备**
（`/sys/block/loopN`、`ioctl(BLKGETSIZE64)`、`BLKRRPART`、分区节点
`/dev/loopNp1` 均可用），因此除"物理介质错误行为"外，其余路径的验证等价。

## 5.7　测试 6：GPT 分区表（sgdisk 规范校验）

```
$ sudo ./build/rufus part -y --scheme gpt --label TESTUSB /dev/loop0
[06:42:41] INFO  创建 GPT 分区表: /dev/loop0（536.9 MB，扇区 512 字节，共 1048576 扇区）

label: gpt
label-id: C4364126-2E57-46D7-8E6E-6AF228E8FCE7
first-lba: 34
last-lba: 1048542

/dev/loop0p1 : start= 2048, size= 1044480, \
    type=EBD0A0A2-B9E5-4433-87C0-68B6B72699C7, \
    name="TESTUSB"
```

### 修复前后对比（重要）

**修复前**：

```
$ sudo sgdisk -v /dev/loop0
Warning! Main and backup partition tables differ!
Warning! One or more CRCs don't match. You should repair the disk!
Main header: OK
Backup header: OK
Main partition table: OK
Backup partition table: ERROR
Problem: The backup partition table overlaps the backup header.
Identified 2 problems!
```

原因：备份分区项被放在 `N-32 .. N-1`，与位于 `N-1` 的备份头重叠。
按 UEFI 规范，备份项应占 `N-33 .. N-2`。

**修复后**：`No problems found.`

**结论**：✅ 通过

- GPT 主/备头、主/备分区项 CRC32 全部正确；
- 分区类型 GUID、分区名（UTF-16LE）、首末 LBA 均正确；
- 权威工具 `sgdisk -v` 报告"无任何问题"。

## 5.22　测试 20：文档一致性核对（1.2.1 新增）

扩写 README 时，对文档里写到的每一条命令与选项做了逐条实测，
因此又暴露出两个缺陷。

### 20.1 缺陷：缺参数调用会先弹授权对话框

`rufus part --help` 在自动化环境下**挂死 60 秒**（超时被 kill）。
原因：`-h/--help` 被 `strip_global_flags()` 静默剥离后，命令行退化成
"`rufus part` 无参数"，而提权拦截发生在参数校验**之前** ——
于是程序先 fork 出 pkexec 请求授权，等着用户在对话框上操作。

```
$ ./build/rufus part --help
[挂死，60 秒后超时]
```

修复后：

```
$ ./build/rufus part --help          # 退出码 0，不弹授权
用法: rufus <命令> [选项] [参数]
命令:
...

$ ./build/rufus part                 # 退出码 1，不弹授权
用法错误："part" 缺少必需参数。
用法: rufus <命令> [选项] [参数]

$ time (./build/rufus create >/dev/null 2>&1)
create 缺参数 退出码=1
real    0m0.006s
```

修复要点：`-h/--help` 提升为全局处理（任何位置、任何子命令都不触发提权）；
新增 `cmd_min_args()` 在请求授权之前检查必需位置参数。

### 20.2 缺陷：`download -n` 与全局 `-n` 选项冲突

`strip_global_flags()` 会把任意位置的 `-n` 当作 `--no-progress` 剥离，
而 `download` 子命令原本也用 `-n` 表示 `--no-verify` ——
结果是**校验永远不会被跳过，且用户毫无察觉**（选项被静默吃掉）。

修复：`download` 的短选项改为 `-N`，长选项 `--no-verify` 不变。
实测 `download -N --list windows` 正常。
