# 第 4 章　用户手册

> Rufus for Linux 1.0.0 —— 命令行与图形界面使用说明

---

## 4.1　安全须知（请先阅读）

> **权限**：本程序**不需要用 sudo 启动**。打开图形界面时会立即弹出系统
> 授权对话框（polkit）；取消授权也可以继续以**只读模式**使用
> （浏览设备、分析镜像、计算摘要、下载 ISO）。命令行需要提权的子命令
> 同样会自动请求授权，`sudo` 方式也仍然可用。
> 详见 [07-polkit授权机制](07-polkit授权机制.md)。

> ⚠️ **本程序会不可恢复地销毁目标设备上的所有数据。**

- 写入、格式化、坏块检测、分区表重建都属于破坏性操作；
- 务必先用 `rufus list` 确认设备路径；
- 程序会**自动拒绝**作为目标的设备：
  - 承载 `/`、`/boot`、`/boot/efi`、`/usr`、`/var` 的磁盘（且 `--force` **无法**绕过）；
  - 只读设备；
  - 非可移动设备（需显式 `--force` 才能作为目标）。
- 块设备操作需要 root 权限。

## 4.2　图形界面（rufus-gtk）

### 启动

```bash
rufus-gtk            # 不要加 sudo
```

启动后会立即弹出系统授权对话框（窗口标题为 "Authentication"），显示本应用
的图标与说明"需要管理员权限才能格式化磁盘设备并向其写入数据"，输入密码
确认即可。

- **确认授权** → 以管理员权限运行，全部功能可用；
- **取消授权** → 进入**只读模式**：顶部显示黄色横幅，"开始"按钮置灰，
  但设备浏览、镜像分析、摘要计算、ISO 下载都仍然可用；
- **`--no-polkit`** → 不请求授权，直接以只读模式启动。

如果桌面环境没有 polkit 认证代理（少见），也可以继续用 `sudo rufus-gtk`。

### 各选项含义

| 控件 | 说明 |
| --- | --- |
| **设备** | 默认可移动设备；选中后会显示容量与型号。写保护/系统盘会被拒绝 |
| **引导选择** | 选择 `.iso` / `.img` / `.wim` 等镜像；选中后自动分析并填充默认值 |
| **分区类型** | `MBR`：兼容 BIOS 与 UEFI-CSM；`GPT`：纯 UEFI 环境推荐 |
| **目标系统** | `BIOS 或 UEFI` / `仅 BIOS` / `仅 UEFI` |
| **文件系统** | `FAT32`（最通用，单文件 ≤ 4 GiB）、`exFAT`（大文件、跨平台）、`NTFS`（Windows 安装盘且 install.wim > 4 GiB 时必需）、`ext4`、`UDF` |
| **簇大小** | `自动` 会按容量阶梯推荐（见 §4.6） |
| **卷标** | 最长 11 字符（FAT）/ 32 字符（NTFS、exFAT）；非法字符自动替换为 `_` |
| **坏块检测轮数** | 0 = 跳过；1–4 = 写入前做 N 轮坏块扫描（耗时随容量线性增长） |
| **可引导 U 盘** | 勾选 = ISO 解包模式（分区 + 格式化 + 复制内容 + 引导器）；不勾选 = DD 原始写入 |
| **写后校验(DD)** | 仅 DD 模式有效：写完后读回比对 SHA256 |

### 命令行参数

```bash
rufus-gtk [镜像文件] [选项]
  --device <路径>   预选目标设备（如 /dev/sdb）
  --all             列出包括非可移动设备在内的所有块设备
  -y, --yes         跳过确认对话框（脚本化使用）
  --auto-start      启动后自动开始写入（配合 --yes 使用）
  --no-polkit       不请求系统授权，直接以只读模式启动
```

示例（无人值守）：

```bash
sudo rufus-gtk --all -y --auto-start --device /dev/sdb ~/ubuntu.iso
```

## 4.3　命令行（rufus）

### 4.3.1　通用形式

```bash
rufus <命令> [选项] [参数]
```

全局开关（可放在任意位置）：

```
-q, --quiet        静默（只输出错误）
-v, --verbose      详细日志（-vv 输出跟踪）
-n, --no-progress  关闭进度条
-y, --yes          不询问确认
-h, --help         帮助
```

### 4.3.2　`list` —— 列出设备

```bash
rufus list           # 只列可移动设备
rufus list -a        # 列出全部块设备
```

输出示例：

```
设备         容量       总线    可移动 只读 已挂载 型号
--------------------------------------------------------------------------------
/dev/sdb     14.9 GB    USB     是     否   否     [USB] SanDisk Cruzer Blade
              序列号: 4C530001120523116142
/dev/sda     214.7 GB   SCSI    否     否   是     VMware,VMware Virtual S

共 2 个设备（其中 USB 设备 1 个）
```

### 4.3.3　`info` —— 分析镜像（只读，安全）

```bash
rufus info ubuntu-24.04-desktop-amd64.iso
```

输出示例：

```
镜像文件      : ubuntu-24.04-desktop-amd64.iso
文件大小      : 5.7 GB (6100000000 字节)
介质类型      : ISO9660
卷标          : Ubuntu 24.04.1 LTS amd64
引导能力      : BIOS + UEFI
  BIOS 引导   : 是
  UEFI 引导   : 是
  混合 MBR    : 是（可直接 DD 写入）
ISO9660       : 是
  块大小      : 2048 字节
  卷内数据    : 5.7 GB (2978526 块)
  Joliet 级别 : 0
  Rock Ridge  : 是
UDF           : 否
Linux 发行版盘: 是
推荐写入模式  : DD 原始写入
```

**判断建议：**

- `推荐写入模式: DD 原始写入` → 用 `rufus create`（默认自动选 DD）或 `rufus write`；
- `Windows 安装盘: 是` → 用 `rufus create`（ISO 解包模式），程序会自动处理
  4 GiB 限制；
- `引导能力: 不可引导` → 只是数据盘，用 `rufus format` 或 DD 写入。

### 4.3.4　`checksum` —— 摘要计算与比对

```bash
rufus checksum ubuntu.iso                          # 默认 SHA256
rufus checksum -a md5 ubuntu.iso                   # MD5
rufus checksum -a sha512 ubuntu.iso                # SHA512
rufus checksum -c <官方公布的摘要> ubuntu.iso       # 比对，返回码 2 表示不匹配
rufus checksum -f ubuntu.iso                       # 强制按文件大小计算
sudo rufus checksum /dev/sdb                       # 对设备整盘计算（需 root）
```

退出码：`0` 匹配 / 不比对；`2` 不匹配。

### 4.3.5　`write` —— 原始写入（DD 模式）

```bash
sudo rufus write ubuntu.iso /dev/sdb
sudo rufus write --verify ubuntu.iso /dev/sdb              # 写后校验
sudo rufus write --verify --hash sha512 ubuntu.iso /dev/sdb
sudo rufus write --force disk.img /dev/sdc                 # 允许非可移动设备
```

选项：

| 选项 | 说明 |
| --- | --- |
| `--verify` | 写完后读回并比对摘要 |
| `--hash <算法>` | 校验算法：`sha256`（默认）/ `sha1` / `md5` / `sha512` |
| `--force` | 允许把非可移动设备作为目标（系统盘仍被拒绝） |

输出示例：

```
写入完成: 6100000000 字节，耗时 128.4 秒，平均 45.3 MB/s
镜像摘要: 8f2c...e91b
设备摘要: 8f2c...e91b
校验结果: 通过
```

**适用场景**：自带混合 MBR 的 Linux ISO、树莓派 `.img`、各类磁盘映像、
任意需要 1:1 复制的数据。

### 4.3.6　`create` —— 创建可引导 U 盘（推荐）

```bash
sudo rufus create ubuntu-24.04.iso /dev/sdb                     # 全自动
sudo rufus create --target both ubuntu.iso /dev/sdb             # BIOS + UEFI
sudo rufus create --fs ntfs --label WIN11 win11.iso /dev/sdb    # Windows 安装盘
sudo rufus create --scheme gpt --fs exfat img.iso /dev/sdb      # GPT + exFAT
sudo rufus create --badblocks 1 ubuntu.iso /dev/sdb             # 先做 1 轮坏块检测
sudo rufus create --mode dd disk.img /dev/sdb                   # 强制 DD 模式
sudo rufus create --mode iso ubuntu.iso /dev/sdb                # 强制 ISO 解包模式
```

选项：

| 选项 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--mode` | `auto`/`dd`/`iso` | `auto` | 写入模式，自动规则见 §4.5 |
| `--target` | `both`/`bios`/`uefi` | `auto` | 引导目标 |
| `--scheme` | `mbr`/`gpt` | `mbr` | 分区方案 |
| `--fs` | `fat32`/`exfat`/`ntfs`/`ext4`/`udf` | 自动 | 目标文件系统 |
| `--label` | 字符串 | 镜像卷标 | 卷标 |
| `--cluster` | 字节数 | 自动 | 簇大小 |
| `--badblocks` | 1–4 | 0 | 写入前坏块检测轮数 |
| `--flash` | `1p`/`2p`/`slc`/`mlc`/`tlc` | `2p` | 坏块模式表 |
| `--verify` | — | 关 | DD 模式下写后校验 |
| `--no-syslinux` | — | 关 | 不安装 SYSLINUX |
| `--uefi-ntfs[=路径]` | — | 自动 | 强制在盘尾添加 UEFI:NTFS 分区；用 `=` 可指定驱动镜像 |
| `--no-conflict-check` | — | 关 | 跳过冲突进程检测 |
| `--force` | — | 关 | 允许非可移动设备；并放行冲突进程 |

它执行的完整阶段（对应 Windows 版 Rufus 的"开始"按钮）：

```
1. 分析镜像（libcdio 读 PVD/UDF/El Torito）
2. 校验目标设备（系统盘/只读/可移动性）
3. 卸载目标设备上已挂载的分区
4. 清除分区表（首尾各 1 MiB 清零）
5. 创建 MBR 或 GPT 分区表（原生写入，1 MiB 对齐）
6. 格式化（mkfs.vfat / exfat / ntfs / ext4 / udffs）
7. 写入分区引导记录 PBR（ms-sys）
8. 挂载 ISO（loop,ro）并复制内容到 U 盘
9. 安装引导器（SYSLINUX / 复制 isolinux）
10. 写入 MBR 引导代码（ms-sys）
```

### 4.3.7　`format` —— 格式化

```bash
sudo rufus format --fs fat32 --label DATA /dev/sdb1
sudo rufus format --fs exfat --label BACKUP /dev/sdb1
sudo rufus format --fs ntfs  --label WIN /dev/sdb1
sudo rufus format --fs ext4  --label ROOT /dev/sdb1
sudo rufus format --fs fat32 --cluster 32768 /dev/sdb1
```

> 只格式化**分区**（`/dev/sdb1`）。若要重建分区表，请先执行 `rufus part`。

### 4.3.8　`badblocks` —— 坏块检测

```bash
sudo rufus badblocks /dev/sdb                   # 1 轮，双模式
sudo rufus badblocks -p 2 /dev/sdb              # 2 轮
sudo rufus badblocks -p 4 --flash tlc /dev/sdb  # 4 轮，TLC 模式表
```

选项：

| 选项 | 说明 |
| --- | --- |
| `-p, --passes <1..4>` | 写入模式轮数 |
| `-F, --flash <1p\|2p\|slc\|mlc\|tlc>` | 闪存类型对应的模式表 |

> ⚠️ **坏块检测是破坏性操作**：它会在整盘写入测试模式，原有数据全部丢失。
> 耗时与容量成正比（USB 2.0 上 16 GB 约需 20–40 分钟）。

输出示例：

```
坏块检测结果 (/dev/sdb, 双次写入(2 轮)):
  测试块数      : 61000
  坏块数量      : 0
  读错误        : 0
  写错误        : 0
  数据损坏错误  : 0
  结论          : 未发现坏块
```

退出码 `4` 表示发现了坏块。

### 4.3.9　`part` —— 重建分区表

```bash
sudo rufus part --scheme mbr --fs fat32 --label USB /dev/sdb
sudo rufus part --scheme gpt /dev/sdb
```

创建一个占据整盘（起始 1 MiB）的分区：

- MBR 方案：分区类型 `0x0C`（FAT32 LBA）或 `0x07`（NTFS），带活动标志；
- GPT 方案：类型 `EBD0A0A2-…`（Microsoft Basic Data），分区名即卷标。

### 4.3.9a　`ps` —— 冲突进程检测

```bash
rufus ps /dev/sdb          # 列出正在占用设备的进程
rufus ps --json /dev/sdb   # JSON 输出（便于脚本处理）
```

输出示例（在一个已挂载的 NTFS 回环设备上）：

```
检测到 3 个进程正在占用 /dev/loop0：

PID      进程               访问       方式             对象/命令行
------------------------------------------------------------------------------------------
49134    mount.ntfs           读写       打开块设备    /dev/loop0p1
           └─ /sbin/mount.ntfs
49520    sleep                只读       打开挂载点文件 /mnt/nt/README.TXT
49574    sleep                cwd          工作目录在设备上 /mnt/nt

这些进程可能会在写入过程中继续访问设备，导致写入失败或数据不一致。
建议先关闭它们（尤其是文件管理器 / 同步工具 / 杀毒软件），重试即可。
```

占用方式共 5 类：`打开块设备`、`打开挂载点文件`、`工作目录在设备上`、
`从设备运行程序`、`交换分区`。

退出码：`0` 无占用；`2` 有占用。

> `create` / `write` / `format` 会**自动**执行这一检查；
> 只有"已挂载"造成的占用会被自动卸载处理，其他占用会拒绝执行。

> 提示：`rufus <命令> --help` 只打印用法，**不会**请求授权；
> 缺少必需参数时也会先提示用法，不会弹出授权对话框。

### 4.3.9b　`download` —— 在线下载 ISO

```bash
rufus download --list                    # 列出全部 53 条
rufus download --list ubuntu             # 按关键字过滤
rufus download ubuntu-2404-desktop-amd64 --dir ~/ISO
rufus download --url https://example.com/x.iso
rufus download --update-catalog <URL>    # 更新目录
rufus download --catalog <文件> <ID>     # 使用指定目录
rufus download --no-verify <ID>          # 跳过 SHA256 校验（不推荐）
```

| 选项 | 说明 |
| --- | --- |
| `--list [过滤词]` | 列出目录条目；可按 id / 名称 / 分类过滤 |
| `--dir <目录>` | 保存目录（默认当前目录） |
| `--url <地址>` | 直接下载任意 URL（不使用目录） |
| `--update-catalog <URL>` | 下载新的目录文件到 `~/.config/rufus-linux/iso-catalog.json` |
| `--catalog <文件>` | 使用指定的目录文件 |
| `-N, --no-verify` | 跳过 SHA256 校验（短选项是 `-N`，因为 `-n` 已是全局的 `--no-progress`） |

下载流程：

1. 查表得到官方 URL 与校验和信息；
2. 优先使用目录内嵌的 SHA256；否则获取官方校验和文件并解析；
3. 用 libcurl 下载（`.part` 临时文件 + 断点续传）；
4. 计算 SHA256 与官方值比对，**不通过则报错并保留文件供人工检查**；
5. 通过后改名为最终文件名。

支持官方校验和文件的多种格式：

| 格式 | 示例 | 发行版 |
| --- | --- | --- |
| coreutils | `<hash>  <file>` | Debian、Arch、Clonezilla |
| coreutils（二进制标记） | `<hash> *<file>` | Ubuntu、SystemRescue |
| BSD 风格 | `SHA256 (file) = <hash>` | Fedora、Rocky、AlmaLinux、FreeBSD、OpenBSD |
| 裸 hash | `<hash>` | Manjaro、openSUSE、Raspberry Pi OS |
| 带路径前缀 | `<hash>  v8.10/<file>` | Memtest86+ |

内置目录覆盖：Windows 评估版（3 条直链 + 2 条官方页面）、Ubuntu、Debian、
Fedora、Linux Mint、Arch、Manjaro、openSUSE、Rocky、AlmaLinux、Kali、
Pop!_OS、elementary OS、Zorin OS、Raspberry Pi OS、FreeBSD、OpenBSD、
GParted Live、SystemRescue、Clonezilla、Memtest86+、Hiren's BootCD PE。

rufus uefi-ntfs      # 显示驱动镜像位置、大小与分区属性

### 4.3.10　`mbr` —— 引导记录

```bash
sudo rufus mbr -t win7 /dev/sdb                        # 写 MBR 引导代码
sudo rufus mbr -t rufus /dev/sdb                       # Rufus 自家 MBR
sudo rufus mbr -p fat32nt /dev/sdb1                    # 写 FAT32 PBR
sudo rufus mbr -t syslinux -p ntfs --keep-label /dev/sdb
sudo rufus mbr -t none /dev/sdb                        # 只识别，不写
```

支持的 MBR 类型（`-t`）：

| 取值 | 说明 |
| --- | --- |
| `rufus` / `rufus-msg` | Rufus MBR（可显示 UEFI:NTFS 提示） |
| `win7` | Windows 7 / Vista MBR（兼容性最好） |
| `2000` | Windows 2000 / XP MBR |
| `dos` / `95b` | 传统 DOS / Windows 95B MBR |
| `reactos` | ReactOS MBR |
| `grub2` / `grub4dos` | GRUB 2 / Grub4DOS MBR |
| `syslinux` / `syslinux-gpt` | SYSLINUX MBR / GPT 保护 MBR |
| `kolibrios` | KolibriOS MBR |
| `zero` | 清零 |
| `none` | 不写入（仅识别当前类型） |

支持的 PBR 类型（`-p`）：

| 取值 | 说明 |
| --- | --- |
| `fat32nt` | FAT32 + NTLDR/bootmgr（Windows 启动盘用） |
| `fat32pe` | FAT32 + PE |
| `fat32dos` | FAT32 + IO.SYS |
| `fat32ros` | FAT32 + ReactOS |
| `fat16` / `fat16ros` / `fat12` | FAT16 / FAT12 |
| `ntfs` | NTFS |

`-k, --keep-label`：写 PBR 时保留原有卷标。

写入的引导代码与 Windows 版 Rufus **完全相同**（使用上游同一份
`mbr_*.h` / `br_*.h` 数据表）。

## 4.4　典型使用场景

### 场景 1：制作 Ubuntu 安装盘

```bash
rufus info ubuntu-24.04-desktop-amd64.iso     # 1. 先看一眼
sudo rufus create ubuntu-24.04-desktop-amd64.iso /dev/sdb   # 2. 制作
```

### 场景 2：制作 Windows 11 安装盘（install.wim > 4 GiB）

```bash
rufus info win11.iso
# 若显示 "install.wim > 4 GiB"，则用 NTFS；
# 程序会自动在盘尾添加 UEFI:NTFS 分区，使 UEFI 固件仍能启动：
sudo rufus create --fs ntfs --label WIN11 win11.iso /dev/sdb
```

产物布局（以 GPT 为例，用 `sgdisk -p` 查看）：

```
Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048         1044479   509.0 MiB   0700  WIN11
   2         1044480         1046527   1024.0 KiB  0700  UEFI:NTFS
```

`UEFI:NTFS` 分区的类型是 **MS Basic Data**（不是 ESP GUID）——
这是刻意的：Windows 安装程序看到两块 ESP 会在"复制 Windows 文件"
阶段报错。该分区还设置了"不分配盘符"属性。

## 4.5　自动决策规则

### 写入模式（`--mode auto`）

```
映像类型 == 磁盘映像(MBR/GPT) 或 原始数据   →  DD 原始写入
Windows 安装盘 且 镜像无混合 MBR            →  ISO 解包模式
其他（Linux ISO / 数据 ISO）                →  DD 原始写入
```

### 目标文件系统（未指定 `--fs`）

```
Windows 安装盘:
    install.wim > 4 GiB  →  NTFS
    否则                  →  FAT32
其他镜像                  →  FAT32
```

### 分区方案

- 默认 `MBR`（兼容性最好，BIOS 与 UEFI-CSM 都能启动）；
- 纯 UEFI 环境或需要 > 2 TiB 分区时选 `GPT`。

### MBR 引导代码（`create` 自动选择）

```
GPT 方案        →  SYSLINUX GPT 保护 MBR
Windows 安装盘  →  Rufus MBR
其他            →  Windows 7/Vista MBR
```

## 4.6　簇大小推荐表

程序按容量自动推荐（`rf_fs_default_cluster()`），沿用上游 Rufus 的
`FAT32_CLUSTER_THRESHOLD = 1.011` 容差系数：

**FAT32**

| 容量 | 簇大小 |
| --- | --- |
| ≤ 260 MB | 512 B |
| ≤ 8 GB | 4 KB |
| ≤ 16 GB | 8 KB |
| ≤ 32 GB | 16 KB |
| > 32 GB | 32 KB |

**exFAT**：≤ 256 MB → 4 KB；≤ 32 GB → 32 KB；更大 → 128 KB

**NTFS**：≤ 512 MB → 512 B；≤ 1 GB → 1 KB；≤ 2 GB → 2 KB；≤ 32 GB → 4 KB；
≤ 32 GB → 4 KB；≤ 64 GB → 16 KB；更大 → 64 KB

用 `--cluster <字节>` 可强制指定。

## 4.8　故障排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 启动后没弹授权对话框，直接进只读模式 | 桌面环境没装 polkit 认证代理 | 安装 `lxpolkit` / `polkit-1-auth-agent` / `mate-polkit`，或改用 `sudo rufus-gtk` |
| 授权对话框显示的是英文 "Run a program as another user" | 策略文件未安装或路径不匹配 | 重新安装本包；确认 `/usr/share/polkit-1/actions/io.github.rufus-linux.policy` 存在 |
| 命令行报 `该操作需要管理员权限` | 未安装 pkexec | `sudo apt install pkexec`，或改用 `sudo rufus ...` |
| 授权成功后程序窗口没出现 | 会话类型特殊（如远程 SSH 转发 X） | 改用 `sudo rufus-gtk` |
| `用法错误："xxx" 缺少必需参数` | 命令参数不全 | 按提示补全；此提示**不会**弹出授权对话框 |

| `拒绝操作: 该设备承载系统根/启动分区` | 目标是系统盘 | 选对设备；此限制不可绕过 |
| `拒绝操作: 设备不是可移动介质` | 目标是内置硬盘 | 确认无误后加 `--force` |
| `拒绝操作: 设备为只读` | U 盘写保护开关 / 只读属性 | 关闭写保护开关；`sudo hdparm -r0 /dev/sdb` |
| `设备忙（请先卸载已挂载的分区）` | 分区已挂载或被占用 | 关闭文件管理器窗口；`sudo umount /dev/sdb1` |
| `设备太小` / `空间不足` | 镜像大于 U 盘 | 换更大的 U 盘 |
| `mkfs.vfat 失败` | 未安装 dosfstools | `sudo apt install dosfstools` |
| `syslinux 安装失败` | 未安装 syslinux | `sudo apt install syslinux syslinux-common`（不影响 UEFI 启动） |
| ISO 解包后 U 盘无法启动（BIOS） | 缺少 BIOS 引导代码 | 用 `sudo rufus mbr -t syslinux /dev/sdb` 补写 |
| Windows 安装报 "install.wim 太大" | FAT32 单文件 4 GiB 限制 | 改用 `--fs ntfs` |
| 进度长时间不动 | U 盘写入慢或出现坏块 | 耐心等待；必要时中止并做 `badblocks` 检测 |
| 校验失败（`--verify`） | U 盘质量问题 | 换 U 盘；或先 `badblocks` 检测 |
| `目标设备正被上述进程占用` | 文件管理器/同步工具/dd 持有设备 | 按提示关闭进程；`rufus ps` 可复查；确认无碍可加 `--no-conflict-check` |
| `该镜像需要 UEFI:NTFS 才能…但找不到 uefi-ntfs.img` | 数据文件未安装 | 重新安装包，或用 `--uefi-ntfs=<路径>` / 环境变量 `RUFUS_UEFI_NTFS_IMG` 指定；也可改用 `--fs fat32` |
| 下载报 `未找到 ISO 目录文件` | 目录文件缺失 | `rufus download --update-catalog <URL>`，或用 `--catalog <文件>` |
| 下载报 `SHA256 校验失败` | 下载损坏或镜像已更新 | 删除已下载文件后重试；若发行版刚发布新版本，更新目录 |

## 4.9　性能参考

在 VMware 虚拟机 + USB 3.0 模拟环境下（4 MiB 分块）：

| 操作 | 吞吐 |
| --- | --- |
| DD 写入（回环设备） | 约 140 MB/s |
| SHA256 计算 | 约 300 MB/s |
| 坏块检测 1 轮 | 约 45 MB/s（写 + 读回） |

实际速度取决于介质。USB 2.0 U 盘通常 5–15 MB/s，USB 3.0 可达 30–100 MB/s。
